# Development notes

How the site's code works: read this before changing the build, templates, styles, or scripts, or when adding a book. For building and previewing, see `README.md`.

## Hosting

The site is served at https://scriptures.conlin.io by Cloudflare, which rebuilds it from this repository whenever `main` is pushed; there is no GitHub deploy workflow. `npm run build` writes a plain static site to `dist/`. `wrangler.jsonc` tells Cloudflare to serve `dist/` and to answer missing paths with `404.html`, which redirects `/Isaiah`, `/isa/53`, and similar paths to their canonical URLs. Its `name` must match the Worker's name in Cloudflare. The repo is at `git@github.com:jlconlin/Scriptures.git`.

## Checks

`scripts/check-content.mjs` (`npm run check`) checks sourcing: unknown keys and wiki URLs everywhere; for chapters with an evidence ledger, every note sourced and every cited key backed by a quoted ledger row. It also warns about chapters well past the length guideline, and about chapters that lean on the Church's Student Manuals (`STANDARDS.md` §1): more than a third of the notes citing one, or notes citing one with no source from beyond the Church's own publications beside it. “Church's own” is decided by the host of the source's URL in `sources.yaml` (`CHURCH_HOSTS` in the script); a source is a Student Manual when its `pub` says “Student Manual”. These are warnings in every chapter, never errors. It is not part of `npm run build`, so unaudited chapters can't break the Cloudflare build. `scripts/check-ledger.mjs` (`node scripts/check-ledger.mjs <book> [n...]`) reopens every ledger row's URL with curl and confirms the quote is on the page, comparing letters only (footnote markers, verse numbers and Strong's annotations get in the way otherwise). It reads a web page as a reader sees it, the footnotes the Gospel Library keeps in the page's embedded data, a raw text or XML file as it is, and a PDF with a text layer; a quote with hardly any letters (a footnote's cross-reference) is compared with its digits kept. On 2026-10-04 it confirmed every row of all three books (Isaiah 2,155, Jeremiah 3,455, Genesis 6,275), after it was taught those forms; 41 Isaiah rows that cited an unreadable ScholarsArchive link now cite Scripture Central's copy of the same book, and one quote was missing its elision. Before that it had only been run on Genesis. pages are cached in `.cache/ledger/` for a day (`--fresh` refetches). It proves quotes are real, not that they support their claims. `scripts/pdf-text.mjs` prints a PDF's text (pdfjs-dist; for research, since Python PDF libraries fail in the cloud sandbox). `scripts/check-kjv.mjs` (`node scripts/check-kjv.mjs <book>`) compares `data/kjv/<book>.json` verse by verse with the Gospel Library edition, including where LORD and GOD are in small capitals; all three books agree with it. Not yet written: `scripts/check-links.mjs` (referenced by `npm run check:links` in `package.json`).

## Writing a book in batches

The steps a coordinating session repeats for every batch of chapters are scripts in the repository, so they are not rebuilt each time (author, 2026-10-04; they were once kept in a scratch folder and lost in a reboot).

- **`.claude/workflows/write-chapters.js`**: the Workflow script. `args`: `book`, `chapters` (about twelve at a time), `writerModel` (`sonnet` by default, or `opus`), `models` (finished chapters of the book to imitate), `focus` (the author's questions, by chapter number). Each chapter goes to a `chapter-writer`, then to a `chapter-checker` (Sonnet), which reopens the sources and writes its findings, then to a `chapter-reviewer` (Opus), which decides them and repairs the chapter (`STANDARDS.md` §11). Run it by name, or with `scriptPath`; if the usage limit or a restart stops it, run it again with `resumeFromRunId` and the same `args`, and finished agents are not repeated. The agents leave working files in `.cache/batch/<book>/` (not committed): `proposed/NN.yaml`, the `sources.yaml` entries a chapter needs, `reports/NN-writer.md`, and the checker's findings, `reports/NN-check.md`.
- **`scripts/merge-sources.mjs <book> <chapters…> [--write]`** gathers the proposed entries and reports what has to be settled by hand: a key already used for another page, one key proposed for two pages, one page under two keys. `--write` appends the rest to `content/sources.yaml`.
- **`scripts/batch-notes.mjs <book> <the run's journal.jsonl>`** reads the reviewers' results and appends the reader questions no source answered to the end of the book's `BRIEF.md` (its last section) and the theme candidates to `THEME-CANDIDATES.md`; it prints anything a reviewer left for the author. The journal's path is in the Workflow tool's result (“Transcript dir”).
- Then the checks (`check-content`, `check-quotes`, `check-ledger`, the build), and one commit per chapter with its ledger.
- **`scripts/preview-site.mjs [out dir]`** builds the site with preview books and makes every link relative, for the claude.ai preview artifact (`AUTHORING.md`, “Showing a change”). It writes the site to `.cache/preview/dist` and the list of files to publish to `.cache/preview/files.json`.

## Site design

- **Margin notes.** On screens 880px and wider (an iPad mini held sideways qualifies; held upright it doesn’t), a note opens in the right margin beside the phrase that opened it, so the text never moves and the reader keeps their place. Several open notes stack without overlapping, and a newly opened note slides up the margin if needed to stay on screen. Narrower screens keep the original behavior (the note opens beneath its verse). The layout is in `src/assets/site.css` (the `min-width: 880px` block; the notes column narrows with the window) and the positioning in `src/assets/site.js` (`layoutNotes`).
- **Related switch.** A toolbar switch shows every note as a compact card (kind, title, and the note’s opening sentence, generated at build time by `teaser()` in `src/templates/chapter.mjs`). Cards sit in the margin on wide screens and under the verse on narrow ones; clicking a card or phrase expands that note and collapses the others. It is off for first-time visitors, and each reader’s choice is remembered. Because the card shows each note’s first sentence, open notes with a sentence that says what the note is about, not a hook like “This is the hardest line in the chapter.”
- **Section headings** (“Background”, “The thread through the chapter”, “In plain words”, and the rest) are defined once, in `SECTIONS` in `src/site.mjs`. Change one there and it changes on every chapter of every book and in the site’s own descriptions. Templates use `book.name`, never a hard-coded “Isaiah”.
- **Reading width:** one setting, `--read-w: 540px` in `site.css`, used by chapters, guides, and the About page (about 55 characters a line in chapters). The author reads mostly on an iPad mini, so check layouts at 744px (upright) and 1133px (sideways).
- **Guides index:** the list of guides and themes (`renderGuidesIndex` in `src/templates/pages.mjs`) is not running text, so it uses its own wider width (`.guides-wide`, 860px) with two columns of cards from 560px up (`.guide-cards-two`). The author preferred two columns to one (2026-10-01).
- **Scriptures menu.** The header's menu is always labeled “Scriptures” (`scriptureMenu` in `src/templates/layout.mjs`; behavior in `site.js`). It lists all five volumes of the standard works, always, and under each the books that are on the site. On screens 640px and wider it opens as one panel of three columns: volume, book, and a grid of chapter numbers (tinted when the chapter has commentary; dashed ones open the Gospel Library). The panel keeps its size, narrowing its columns a little below about 740px. With a mouse, pointing at a volume or book opens its column and clicking goes to its page; on a touch screen the first tap opens the column and a second tap goes to the page; the name at the top of each column also links there. Narrower screens show one column at a time with a back button. It opens where the page is (current volume, book, and chapter), closes on any choice, a click elsewhere, or Escape, and without JavaScript is a plain list. Beside it: Guides (on pages of a book that has guides), About (680px and up; in the menu on narrower screens), and Search. Each volume's color is a `--v-<volume slug>` variable in `site.css`.
- **Home page library.** The home page's library is the Scriptures menu's picker, open on the page (`.picker` in `renderHome`, `src/templates/pages.mjs`; drawn by `site.js` from the menu's data plus each book's `home.blurb`). It shows the five volumes, the books under the chosen one, and the chosen book's blurb, links, and chapter numbers, so it is the same size however many books there are. Here a click only selects; the names at the top of each column are the links. Under 640px it is a list of volumes and books, and a book opens its chapters in place. The reader's last book is remembered. The hero's “Choose a book” button scrolls to it. Nothing on the home page names a particular book.
- **Home page notes.** “Try a phrase” shows three note cards, chosen at random when the site is built (`renderHome`). A quiet “Show three more” link under the cards (a button beside the heading stood out too much; author, 2026-10-03) replaces them with three others chosen in the browser (`site.js`). The build writes every note of every built book to `notes.json` at the site root, with only what a card needs (book, chapter, verse, id, kind, phrase, and the first 150 characters of the note); the page fetches it on the first click, not when it loads. The cards drawn in the browser have the same markup as the built ones; each kind's chip (icon and label) comes from a hidden `<template class="teaser-chip">` that `renderHome` writes from `KINDS`. Only notes with a phrase under 60 characters are drawn, the same rule the build uses. The button is hidden until `site.js` shows it, so without JavaScript (or if `notes.json` can't be fetched) the three built cards stay.
- **Volume pages.** `/old-testament/`, `/new-testament/`, `/book-of-mormon/`, `/doctrine-and-covenants/`, and `/pearl-of-great-price/` list that volume's books on the site and link to the volume in the Gospel Library. The five volumes are in `src/lib/canon.mjs`; a book's volume and its place in it come from its `abbr` and the scripture-reference table in `src/lib/refs.mjs`. Book pages link their eyebrow to their volume's page.
- **Search** has a book filter once there is more than one book; each `search.json` entry carries its book's slug in `b`.
- **Highlighted phrases** are `<span role="button" tabindex="0">`, not `<button>`, so they wrap across lines like ordinary text; `site.js` gives them Enter and Space.

## Books

The build treats every directory `content/<slug>/` that has a `book.yaml` and a `chapters/` directory as a book, and builds each under `/<slug>/`. `src/lib/books.mjs` does the discovery (the build and the scripts share it); `LIBRARY` in `src/site.mjs` is the list of books that templates read (header nav, 404 redirects, internal `[[…]]` links). Everything Isaiah-specific lives in `content/isaiah/book.yaml`. Scripts take the book as an optional first argument (`node scripts/show.mjs jeremiah 1`, `node scripts/check-quotes.mjs jeremiah 1`), defaulting to `isaiah`. `scripts/fix-yaml.mjs` with no arguments still touches Isaiah only; `npm run build` runs it with `--all`. `BUILD_OUT=<dir>` makes the build write there instead of `dist/` (for agents that run the build as a check at the same time). For comparing two builds byte for byte, `BUILD_VERSION=x BUILD_SEED=1 node scripts/build.mjs` pins the `?v=` stamp and the home page's random teasers.

**Preview and live.** A book whose `book.yaml` has `status: preview` is built only by `npm run dev` and `PREVIEW=1 npm run build` (use this for the claude.ai preview); the live build leaves it out completely. With no `status`, a book is live.

**Unwritten chapters.** A chapter with no YAML file is unwritten. It gets no page and is left out of search and the sitemap. On the book page its card is greyed out and opens the chapter in the Gospel Library; the chapter strip dims its tick and links there too; previous/next links skip it; `[[Jer. 5:1]]` links to the Gospel Library until the chapter is written (`LIBRARY` carries each book's written chapters for `src/lib/refs.mjs`); and `404.html` sends `/jeremiah/5/` to the Gospel Library. The home page card and the header menu say “N of 52 chapters” until the book is complete.

Markdown files at the top of a book's directory (`BRIEF.md`, `THEME-CANDIDATES.md`, and so on) are project notes; the build ignores them. Markdown in `guides/` and `themes/` is published.

### Adding a new book

The author's brief for the book comes first (see `AUTHORING.md`). Then:

1. `node scripts/fetch-kjv.mjs Jeremiah` writes `data/kjv/jeremiah.json` (the source file name has no spaces, such as `1Samuel`; a second argument sets a different slug). Then run `node scripts/check-kjv.mjs <slug>`, which lists every verse that differs from the Gospel Library edition (spellings, hyphens, punctuation, and LORD or GOD in small capitals); add the differences to `LDS_SPELLINGS` in `fetch-kjv.mjs` and import again until it reports none.
2. `content/<slug>/book.yaml`, starting with `status: preview` (remove it when the book should go live; see “Preview and live” above). Required: `name`, `slug` (the directory name), `order` (nav and home-page position; lowest first), `abbr` (the abbreviation `src/lib/refs.mjs` uses, such as `jer`; `[[Jer. 1:5]]` links to the book from then on, and it decides which volume the book is listed under and where), `gospelLibrary` (path under `…/study/scriptures/`, such as `ot/jer`), `eyebrow` (line above the title, such as “The Old Testament”; it links to the volume's page), `heroQuote` (`text`, `cite`), `description` (meta description of the book page), `divisionsBlurb` (subtitle of the division map), `home` (`blurb`, the one-line description in the home page's library and on the volume page), `intro`, `divisions` (each `key`, `range`, `name`, `blurb`, and a `color`), `beloved`, `coreSources`, and optionally `rangeSources` and `titles`. `content/isaiah/book.yaml` is the model.
3. Division colors: each division gets `color` and, for dark mode, `darkColor` (defaults to `color`). The build appends them to `dist/assets/site.css` as `--div-<key>` variables; it warns when a division has neither a `color` nor a variable in `site.css`. Isaiah’s colors stay in `site.css` (moving them would change its output). The variables are global, so **give a new book’s division keys names that Isaiah doesn’t use** (`judah`, `nations`, `apocalypse`, `woes`, `hezekiah`, `comfort`, `servant`, `zion`).
4. Chapters in `content/<slug>/chapters/NN.yaml`; guides and themes as Markdown in `guides/` and `themes/`. A chapter with no file is unwritten (see above); `titles` in book.yaml can give unwritten chapters a title on the book page.
5. Book of Mormon comparison data is optional: `data/bom/<slug>-parallels.json`, same format as Isaiah’s (only Isaiah has one; `scripts/fetch-bom-parallels.mjs` is Isaiah-specific). Without it, chapter pages simply have no BoM panel.
6. Still written by hand for now: site-wide wording that names books (`SITE.description`, the 404 page’s Isa. 30:20 line, the search box’s example searches).
